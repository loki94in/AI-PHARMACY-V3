# React Frontend Application (frontend/)

This directory contains the Single Page Application (SPA) built using Vite, React, TypeScript, and TailwindCSS.

## Scope & Responsibilities
- **Pages & Components**: React views, settings panels, dashboard, etc.
- **UI Guidelines**: 
  - Never hardcode raw Tailwind colors like `bg-black/20`, `text-white`, or `bg-white/5` (which break light/dark themes).
  - Use semantic variables: `bg-bg`, `bg-bg2`, `bg-bg3`, `bg-glass-bg`, `text-text`, `text-muted`, `border-border`, `border-glass-border`.
  - **Transparent page roots (added 2026-08)**: page-level root containers MUST NOT paint a solid background (`bg-bg` removed from all 24 page roots incl. CRM's patient/chat panes) — every page sits directly on the global body background. Cards, panels, inputs and modals keep their semantic surfaces.
  - **Solid-surface sweep complete (added 2026-08-25, bug P3-09)**: every remaining raw opaque surface was tokenized at source (Purchases upload/distributor modals + hover-intel popovers, BackupCenterModal buttons, Dispatch avatar/toggle-track, CatalogUpload mapping modal/headers/options, PhoneSales timeline node, InfiniteTable/StickyTable headers → `bg-glass-bg`, Purchases/Sells drawers → `bg-glass-bg`, StagedQueueFloatingWidget + MobileConnectionModal cards) and the now-dead `.light` gray/zinc/hex shim blocks were deleted from index.css. NEVER reintroduce bare `bg-white`, `bg-black`, `bg-gray-*`, `bg-zinc-*` or `bg-[#hex]` container surfaces; guardrail F6 blocks them on changed lines. Sanctioned solids remain: camera video stage, QR/barcode white tiles, print portal whites, opacity scrims (`bg-black/50`+), and toggle knobs/dots.

- **Apple reskin (added 2026-10-09, see `APPLE_DESIGN_RESKIN_PLAN.md`)**: font stack is `-apple-system, SF Pro Text, Inter`; default radius 16px (presets Compact 8 / Standard 16 / Curved 20, same DB keys); cards `rounded-2xl`, sheets/modals `rounded-3xl`; the ONLY large shadow is `shadow-[0_4px_24px_rgba(0,0,0,0.12)]` (no `shadow-2xl`); sidebar active item is a flat `bg-primary/15` pill; tab strips use `components/common/AppleSegmented.tsx` (solid track `bg-bg3`, thumb `bg-bg`). Press feedback is `active:scale-[.98]` (transform only). Radius presets are live: `tailwind.config.js` maps `rounded-xl/2xl/3xl` to `--app-border-radius` (×0.75 / ×1 / ×1.5), so use those classes for cards/modals/inputs. All `backdrop-blur-*` tokens were stripped repo-wide (dead under the no-GPU lock) — do not add them back; full-screen `inset-0 bg-black/50+` scrims stay sanctioned. Global `button:active` press scale lives in `index.css`. No blur, no hover translate lifts, no endless animations — still bound by the No-GPU contract.

## Development Rules
- Start the frontend dev server using `npm run dev` from the `frontend/` folder.
- Run `node scripts/quick-update.mjs` at the project root after adding or updating frontend components.

## UI Component Constraints & Layering Rules
- **Z-Index Unification**: Avoid hardcoded z-index utilities like `z-[99999]` or `z-[999999]`. Always use the semantic tailwind tokens:
  - Dropdown: `z-dropdown` (999)
  - Sticky Headers: `z-sticky-header` (1000)
  - Sliding Drawers: `z-drawer` (9000)
  - Page Modals: `z-modal` (9999)
  - Lightbox / Fullscreen Overlay: `z-global-modal` (10000)
- **Modal Interaction**: If a modal (e.g. Universal Edit) is opened from a drawer panel, the drawer panel must be closed (`setPanelOpen(false)`) to prevent layering overlaps.
- **Alert & Confirm Dialogs**: Avoid using native blocking browser `alert()` or `confirm()` dialogs in new code. Use custom UI toast triggers (`toastEvent.trigger(msg, 'success' | 'error')`) or styled modal overlays.

## Autocomplete Dropdown Gating Rule (added 2026-08)

- A search/autocomplete dropdown list must NEVER appear (and must never trigger its network fetch) from focus or click alone. It may only open when the user has TYPED at least 2 characters (Purchase medicine rows keep their existing ≥3-char rule) AND results exist. Applies to every page: POS patient/doctor/medicine, Purchases distributor/medicine, CRM special-order rows, Pharmarack search, and any future autocomplete.
- Never re-add unconditional `onFocus`/`onClick => setOpen(true)` on a search input, and never seed dropdowns with fabricated/default entries (the hardcoded POS default doctors were removed under this rule).
- Live Cart search queries live upstream Pharmarack OpenSearch via `api.searchPharmarack`. When Pharmarack is disconnected, offline, or returns 0 results, the backend search cleanly falls back to local pharmacy purchase history and distributor catalogs as governed by the `combine_pharmarack_pharmacy_search` toggle in Settings (default enabled). Distinct distributor rates and MRPs are presented in the same rich card format.
- Live Cart add is STAGE-STYLE (added 2026-08): `selectSuggestion` MUST abort the in-flight keystroke search (`searchAbortControllerRef`) — after a selection no newer controller exists, so an un-aborted late response passes the stale-guard and repaints the just-closed dropdown ~100–200ms later. `handleSubmit` stages into a module-cached pending queue (`pendingAddsCache`: adding → added / failed+Retry chips, auto-clear 4 s) and resets the form INSTANTLY; the upstream `api.addPharmarackCart`, source-order `Ordered` flip, and cart/pending refreshes run detached via `processBackgroundAdd` (fires existing `refresh-pharmarack-cart` on success only). Never revert to a blocking submit that awaits the upstream add before resetting the form, and never show a success state for a failed background add.

## Dropdown Scroll Performance Rule (added 2026-09-30, bug P2-56)

- Electron renders in software by owner policy: the app must never need a graphics card (root AGENTS.md "No-GPU Desktop Rendering Contract", guardrail E1). Every repaint therefore costs CPU. The scrolling element of EVERY dropdown/autocomplete list MUST carry `dropdown-scroll` (defined in `index.css`: composited scrolling, `overscroll-behavior: contain`, no row transitions, static `animate-pulse`/`animate-ping` badges). Put it on the element that actually has `overflow-y-auto`, not on a non-scrolling wrapper.
- Mouse-driven row highlight MUST use `onMouseMove={() => { if (highlight !== idx) setHighlight(idx); }}`, never `onMouseEnter`. Rows sliding under a still cursor during a scroll fire mouseenter, which re-rendered the entire POS/Purchases/CRM page once per row.
- Dropdown panels are always opaque (2026-10-04): `index.css` gives any element that directly wraps a `.dropdown-scroll` list `background-color: var(--bg2)` + shadow, matching the Live Cart Add list. Never use `bg-*/NN`, `bg-transparent` or no background on a dropdown panel.
- Never re-add `backdrop-filter` to sticky headers or a hover translate/`transition-all` to `.glass-panel`: both were CPU repaints on every scroll frame.
- Attention animations are finite (bug P2-57): `index.css` caps `animate-pulse` / `animate-ping` / `animate-bounce` at 3 cycles, because an endless one keeps the CPU redrawing at idle. Never override that with `infinite` or add new endless keyframe animations; only `animate-spin` loaders stay endless. To re-draw attention, re-apply the class (re-mount or toggle it) instead.
